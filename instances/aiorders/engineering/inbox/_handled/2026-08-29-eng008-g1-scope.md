# G1 — Influencer board admin management — region/campaign-type preference, rating, collaboration count

## Readback

**You said:** "for the influencer board on admin panel we are unable to see
or edit the preference of the influencer in a certain area or update those.
also information on the engagement is missing . influencers should only be
able to see the opportunities available but only be able to apply to ones
they selected for their region. also same thing for the type of campaign
paid or barter. on admin side our staff should be able to rate or add the
number of collaborations the influencer has done with us" (full input
preserved in the ticket's own `## Input`,
`agents/eng-manager/board/ENG-008-influencer-profile-admin-management.md`)

**Understood as:** The influencer board on the admin panel is missing data
staff need to manage influencers — region preference, campaign-type
preference, a rating, and a collaboration count — and separately,
influencers should eventually only be able to apply to opportunities
matching their own region/campaign-type. **This ticket is the first half
only**: the admin-side data. The second half (influencer-facing gating)
depends on this one and is proposed as the next ticket, filed once this
verifies. A third piece — "engagement" — is a standing, non-blocking
question already with you separately
(`inbox/2026-08-29-eng008-engagement-source-question.md`), since it swings
scope by roughly an order of magnitude and isn't answerable from the
request text.

**Requirements for this ticket:**
1. `[stated]` Staff can see an influencer's preferred region(s).
2. `[stated]` Staff can edit and update an influencer's preferred
   region(s).
3. `[inferred]` Staff can see and edit an influencer's preferred campaign
   type(s) (paid, barter, or both).
4. `[stated]` Staff can rate an influencer.
5. `[stated]` Staff can view and update a collaboration count.

**Assumed, and worth correcting if wrong:**
- Campaign-type preference allows more than one selection, not a forced
  single choice.
- Collaboration count is a manually staff-edited number, not a derived
  ledger.
- Rating is staff-only — not shown to the influencer or publicly.
- An influencer record and admin board already exist to extend — confirmed
  by reading `aiorders-api`'s live backend
  (`restaurant-influencer-campaigns`, `outgoing-communications/actors/influencers.ts`,
  `migrate-influencer-images`), not assumed.

**Not doing (this ticket):** influencer-facing opportunity visibility or
apply gating (item 2); engagement info of any kind (standing question);
a full collaboration history/ledger, only a count; any influencer
self-service editing of rating or collaboration count.

## Recommendation

**Build ENG-008 now.** Independently useful to staff on its own (rating
and collaboration tracking need nothing else), it's the direct
prerequisite for the influencer-facing gating you also asked for in the
same message, and it carries zero influencer-facing risk — nothing an
influencer sees or can do changes until item 2 lands on top of it.

## Problem

Staff can't see or set an influencer's region/campaign-type preference,
rate them, or track collaboration history on the admin board today, so
matching and vetting influencers happens off-system.

## Acceptance criteria

1. `[stated]` Given an influencer with no region set, when staff set one
   or more preferred regions, then the admin board displays them and they
   persist.
2. `[stated]` Given a region already set, when staff edit it, then the
   board reflects the update.
3. `[inferred]` Given no campaign-type preference set, when staff set
   paid, barter, or both, then the board displays and persists it.
4. `[inferred]` Given a campaign-type preference set, when staff edit it,
   then the board reflects the update.
5. `[stated]` Given no rating, when staff set one, then the board displays
   it and it persists.
6. `[stated]` Given an existing rating, when staff change it, then the
   board reflects the new value.
7. `[stated]` Given no collaboration count, when staff set or increment
   it, then the board displays the current count and it persists.
8. `[proposed]` Given a non-staff request to any write path above, then
   it's rejected by the same authorization gate the rest of the admin
   portal already uses.

## Non-goals

Influencer-facing gating (item 2, filed once this verifies); engagement
info (standing question, separate); a collaboration history ledger; any
frontend outside `aiorders-admin-hub`'s admin board; influencer
self-service editing of staff-only fields.

## Risks and unknowns

- The existing influencer-campaign backend
  (`restaurant-influencer-campaigns`) reads as invitation-based, not an
  open browsable list — relevant to item 2's design, flagged now so it
  isn't a mid-build surprise later.
- Region granularity (city/province/fixed list/radius) is undefined — left
  for the architect; doesn't change this ticket's acceptance criteria.
- No stated deadline.

## Cost

Build: `M` — spans `aiorders-api` (schema/endpoint) and
`aiorders-admin-hub` (admin UI); each half is simple on its own. Run:
`$0/month` — no new vendor.
