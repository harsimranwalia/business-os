# P0 — anyone can trigger a real customer message send on the autopilot API, no login or key needed

**What's wrong.** The `autopilot` edge function has a second problem beyond
`ENG-029` (already reported): one of its routing branches — the "system
triggered" marketing actions — skips authentication entirely, checking only
a plain true/false flag that the caller supplies themselves in the request.

**What that means concretely.** Anyone, with no app key and no login at all,
can send a request that makes the system email or text a real customer a
"welcome offer," attributed to whichever restaurant they name — repeatably,
at your cost, for any customer/restaurant pairing they already know. This is
a different kind of problem than `ENG-029`'s (that one leaks data; this one
lets a stranger make the system take a real action).

**Why this is reaching you now instead of Friday's report.** Same rule
`ENG-022`/`ENG-029` used — a live exploit in production is one of the two
things allowed to interrupt you directly
(`agents/eng-manager/config/security-baseline.md`).

**What's already happening.** This doesn't need your approval to start —
`security`-typed tickets skip the approval step by design. `ENG-035` is
filed and handed to the architect for the design step; full evidence is on
the ticket:
`agents/eng-manager/board/ENG-035-autopilot-systemtriggered-auth-bypass.md`.

**How this was found.** Not a security sweep — a byproduct of `ENG-029`'s own
design work (reading the same file in full to design that fix surfaced this
separate branch).

**What would help from you, if anything.** Nothing is required. If you want
this to jump ahead of everything else in flight, you can set `priority: now`
on `ENG-035` — that's the one thing only you can do here. Otherwise it
proceeds at its own severity's normal speed.
