# P0 — the autopilot API is leaking customer contact data across restaurants right now

**What's wrong.** The `autopilot` edge function (the API behind the brand
portal's "Automations" page) never checks that the caller actually owns the
restaurant they're asking about — on any of its 8 actions — and it doesn't
even require a logged-in session, only the app's own public API key.

**What that means concretely.** Anyone who can reach this endpoint — which
needs only the same public key every visitor's browser already has, not a
real login — can pull up another restaurant's customer communication history
(name, email, phone, message content) and can read, edit, disable, or delete
another restaurant's automated-message templates. No special tools needed,
just a different restaurant ID.

**Why this is reaching you now instead of Friday's report.** Same rule
`ENG-022` used — exposed data, live, in production, is one of the two things
allowed to interrupt you directly
(`agents/eng-manager/config/security-baseline.md`).

`security`-typed tickets skip the approval step by design. `ENG-029` is
filed and handed to the architect for the design step; full evidence is on
the ticket:
`agents/eng-manager/board/ENG-029-autopilot-restaurant-scoping-broken.md`.

**How this was found.** Not a security sweep — a byproduct of `ENG-019`'s own
tech-design research (it reads this same send system as reusable prior art
for the new broadcast feature).

**What would help from you, if anything.** Nothing is required. If you want
