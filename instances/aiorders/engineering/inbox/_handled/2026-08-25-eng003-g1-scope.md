# G1 — Untrack `.env` from config-site-builder and close related env-hygiene gaps

## Readback

**You said:** "`.env` is tracked in config-site-builder and unignored in
aiorders-admin-hub... The Google Maps key is the one worth an actual look: it
is billable, and if it carries no HTTP-referrer restriction in Google Cloud
it can be lifted from the bundle and spent by anyone... [1] Check/restrict
the Maps key. [2] Get `.env` out of tracking in config-site-builder,
`.gitignore` in both repos, plus a committed `.env.example`. [3] Decide
whether rotation is warranted. Also... `restaurant-marketplace/.claude/projects/`...
worth one line in the same pass." (`inbox/requests/2026-08-23-aiorders-env-hygiene.md`)

**Understood as:** Ship the repo-hygiene pieces now — untrack `.env` in
`config-site-builder`, `.gitignore` it in both repos, add a `.env.example`
each, and add the one-line `.gitignore` fix in `restaurant-marketplace`. Hand
the Maps-key referrer check and any rotation decision back to you explicitly,
because both are Google Cloud / Supabase console operations and nothing in
this department's configuration shows it has access to either console.

**Requirements:**
1. `[stated]` Untrack `config-site-builder/.env`, `.gitignore` it in both
   repos, add a `.env.example` to each.
2. `[stated]` `restaurant-marketplace/.claude/projects/` gets a `.gitignore`
   entry.
3. `[stated]` Determine/restrict the Maps key's referrer restriction, and
   decide on rotation — flagged back to you, not executed by this ticket.
4. `[inferred]` "Untrack" means going forward (tip-only), not a git-history
   rewrite.

**Assumed, and worth correcting if wrong:**
- That the department has no Google Cloud / Supabase console access at all —
  if that's wrong, this ticket's scope should grow to include the check
  directly rather than handing it back.
- That you want the tip-only untrack, not a full history scrub of the secret
  values — the two are very different sizes of work, and the request
  doesn't say which.

**Not doing:** checking/restricting/rotating any cloud-console credential;
rewriting `config-site-builder`'s git history; touching the uncommitted
`VITE_BRAND_ID` edit; `.env` hygiene on `aiorders-api` or `restaurant-portal`;
pre-commit secret-scanning tooling.

## Recommendation

**Approve as scoped.** The git-hygiene half is a clean, low-risk, low-cost
fix to a real (if slow-burning) footgun, and it's the only half this
department can actually execute. The Maps-key half is the part with a real
dollar cost attached, and the honest answer is that it needs you, not a
ticket — this G1 puts that in front of you explicitly rather than letting a
ticket's "done" quietly imply it was checked.

## Problem

`config-site-builder/.env` is tracked in git, holding live Supabase and
Google Maps values; neither repo's `.gitignore` mentions `.env`. Re-verified
this pass (2026-08-25): the values are already public-by-design in the
shipped Vite bundle regardless of git tracking, so the real, uncertain risk
is entirely on the Maps-key side — whether Google Cloud restricts it by HTTP
referrer — which this department cannot check.

## Acceptance criteria

1. `[stated]` `config-site-builder`'s `.env` is untracked and `.gitignore`d;
   a committed `.env.example` names its real variables.
2. `[stated]` `aiorders-admin-hub` ignores `.env` and carries its own
   `.env.example`.
3. `[stated]` `restaurant-marketplace` ignores `.claude/projects/`.
4. `[stated]` The Maps-key check and rotation decision are named back to you
   as your own action items, not silently marked done.

## Non-goals
