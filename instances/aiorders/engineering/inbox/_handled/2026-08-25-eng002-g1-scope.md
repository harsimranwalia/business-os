# G1 — Add a smoke-test harness to restaurant-portal

## Readback

**You said:** "No registered AIOrders project has a single test... Shape and
scope this. The department decides the shape — this is a problem statement,
not a design... Start with one repo, not five. `restaurant-portal` has a
clean working tree and already builds... `aiorders-api`... probably
deserves its own ticket rather than being folded into a frontend harness."
(`inbox/requests/2026-08-23-test-harness.md`)

**Understood as:** Give `restaurant-portal` a real, working test command and
at least one real test — not a placeholder — that would fail if the build
broke or a route stopped rendering. The other three frontends and
`aiorders-api` stay out of this ticket.

**Requirements:**
1. `[stated]` One registered repo gets a real, runnable test command.
2. `[stated]` `aiorders-api` and the other three frontends are out of scope
   for this ticket.
3. `[inferred]` "Real" means it can fail — not a suite that always passes.
4. `[proposed]` `restaurant-portal` is the repo, on the request's own
   technical read; the architect can pick a different frontend if design
   turns up a reason to.

**Assumed, and worth correcting if wrong:**
- "Before anything else ships" is read as urgency framing, not an instruction
  to hold other tickets — if it's meant literally, that needs `priority: now`
  from you directly, not an inference.
- No other repo is promised a follow-up ticket by this one — `aiorders-api`
  will likely need its own, but that's not committed here.

**Not doing:** comprehensive coverage, the other three frontends,
`aiorders-api`, any change to `restaurant-portal`'s behaviour, a hosted CI
pipeline.

## Recommendation

**Approve as scoped.** This closes a real hole (the QA gate currently
proves nothing on any AIOrders ticket — see Problem) at the cheapest size
that produces a real fix: one repo, smoke-level, no comprehensive-coverage
detour. It's also the ticket that satisfies `ENG-001`'s last open acceptance
criterion (one real ticket reaching `shaped`).

## Problem

`lib/eng-gate-check.sh` verifies a receipt file exists and is non-empty —
never its contents. `skills/test-suite-run/SKILL.md` already writes an
honest "no suite" result when there's nothing to run, but that write still
produces a non-empty QA receipt. Net effect: every AIOrders ticket's quality
gate currently passes regardless of whether any test ever executed, because
none of the five repos has one. Re-verified this pass (2026-08-25): still
true.

## Acceptance criteria

1. `[stated]` `restaurant-portal`'s test command executes real test code and
   exits non-zero on a failing test.
2. `[stated]` A change that breaks the build or stops the entry route from
   rendering makes the suite fail.
3. `[stated]` `agents/eng-manager/config/projects.md`'s Test cell for
   `restaurant-portal` names the real command.
4. `[inferred]` `skills/test-suite-run/SKILL.md` executes the new suite and
   returns a non-vacuous result against `restaurant-portal`.

## Non-goals

Comprehensive coverage; the other three frontends; `aiorders-api`;
`restaurant-portal`'s actual behaviour; a hosted CI pipeline. Full detail in
the PRD.
