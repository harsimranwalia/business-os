# G1 — Restaurant marketing broadcasts (ENG-019)

## Readback

**You said:** "client/brand page/portal autopilot on brand portal does not
have mass/ drip campaign options for client/restraurant to use to send for
any new menu drop or holiday they cant schedule or run any manual campaigns
for their data and generate/track roi of the campaigns"

**Understood as:** restaurant owners on the brand portal want to message
their own customers on their own initiative — a one-time blast or a
multi-step drip, for an occasion they choose — sent immediately or
scheduled, with visibility into whether it produced orders. Today the only
customer-messaging system on the brand portal (`Automations`) is entirely
reactive; nothing lets an owner act on their own list on their own timing.

**Second reading:** the PM's reading (grounded in the brand portal/
admin-hub/`aiorders-api` code directly) and a blind architect reading
independently converged on the same core shape — no material divergence,
so this goes straight to G1 rather than a standing question.

**Assumed, correctable here:**
- "Campaign" means a new customer-facing broadcast, distinct from the
  brand portal's existing (unrelated) influencer-invite "Campaigns" nav
  item — proposed working name "Broadcasts" to avoid the collision.
- Audience = the restaurant's own existing customer list (all, or inactive
  for a chosen number of days). A fuller segment builder is later work.
- Channels: email and SMS only, matching every other send path this
  platform already has.
- "ROI" = a coupon code on the campaign, reusing the existing offers
  mechanic — redemptions and the revenue behind them show on the
  campaign's own page. Open/click tracking and no-code attribution are
  later work.
- Content is owner-authored, not generated from the menu catalog.
- Restaurant owners/managers only — not partner-admin/partner-user
  (agency/reseller); same reasoning `ENG-017` used, and `ENG-015` is
  already fixing a related cross-tenant gap elsewhere.

**Not doing (this ticket):** deeper ROI/attribution beyond coupon-code
redemption, a multi-condition segment builder, AI-generated content, a new
outbound channel, reseller access, or any change to the existing reactive
`Automations`. All named as later, separate work in the PRD's Non-goals,
not dropped.

**Flagged, not a divergence:** the architect's blind reading raised CASL
consent (real but lower-stakes than `ENG-017`'s cold leads — this audience
already has a prior order relationship), cross-tenant scoping (this
codebase's confirmed history — `ENG-015` — is why acceptance criterion 7
exists), and durable scheduling infrastructure for drips (a design
question, not a scope one). Full detail:
`agents/product-manager/specs/ENG-019-restaurant-marketing-broadcasts.md`.

## Recommendation

Build now, scoped as above. `L` — a new campaign/audience/scheduling data
model, an owner-facing composer/reporting UI (`restaurant-portal`), and a
fan-out send path plus drip scheduler reusing existing send services
(`aiorders-api`), same shape `ENG-017` used for lead nurture. No new
vendor, $0/month expected. Full PRD:
`agents/product-manager/specs/ENG-019-restaurant-marketing-broadcasts.md`.
