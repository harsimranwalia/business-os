# G1 — Website chat-bar engagement visibility (ENG-021)

## Readback

**You said:** "the search /chat bar engagement on website is not displayed/
visible on the brand portal. so unable to show restaurant owner its benefit
of help them make their faq's better restaraut customers visit or questions
on the serch/chat bar but we are not able to make it useful for them or the
restaurant owners"

**Understood as:** every restaurant's public website already has a live AI
search/chat bar customers use to ask real questions. None of that
activity — the questions, or the fact that it's happening — is visible
anywhere on the brand portal, so the owner has no way to see the feature
working or to turn a real question into a better FAQ answer. A visibility
and self-service gap, not a missing capability in the chat bar itself.

**Second reading:** no material divergence. The PM's reading (grounded in
live code across `config-site-builder`, `aiorders-api`, `aiorders-admin-hub`,
`restaurant-portal`) and a blind architect reading converged on the same
shape — capture → surface to the owner → act on it via FAQs, as a closed
loop, on the brand portal. The architect's from-first-principles reading
correctly flagged as open questions several things the code-grounded reading
was able to confirm directly: queries are already captured durably per
restaurant; the owner's account already has backend read access via an
existing but entirely unused RLS policy; FAQ content today is staff-only,
edited in the internal admin tool. None of these resolutions changed the
shape of the request, only its cost — cheaper than either reading alone
suggested, since most of the plumbing already exists.

**Assumed, correctable here:**
- "Search bar" and "chat bar" are the same widget (confirmed in code: one
  component, `AISearchBar`, opens the chat panel).
- "Make their FAQ's better" means the owner can act on what they see — add
  or edit the FAQ content the bot uses — not just view a report and email
  AIOrders staff. Read literally against this board's current self-service
  pattern (`ENG-014`, `ENG-015`, `ENG-019`).
- The relevant FAQs are the general website FAQs the chat bot draws answers
  from — not the separate, catering-page-specific FAQ list restaurant-portal
  already lets owners edit today (confirmed as different fields).
- Scope is the brand portal (owner-facing), per the literal request — not a
  staff-facing admin-hub view.

**Not doing (this ticket):** scoring or flagging which questions the bot
answered badly (no such signal exists today), clustering/deduplicating
near-identical questions, a staff-facing admin-hub mirror, any change to the
chat bar's own runtime behavior or answer quality, any change to the
existing conversation-retention/cleanup job, or redacting/scrubbing PII from
the displayed questions (named as a risk for the security gate, not resolved
by omission).

**Flagged, not a divergence:** PII in free-text queries — customers can type
anything, including phone numbers or health/allergy details; the owner is
arguably the right custodian of their own customers' data (the existing
access rule already assumes this), but the architect and security gate
should look at this plainly. RLS on the FAQ table is assumed, not
confirmed — the PM did not read the literal policy text, inferring write
access from a sibling brand-portal page (`hiring`) that reads/writes the
same table; the architect should confirm at design time. Retention window
and per-restaurant query volume are both unknown, worth a quick check at
design time rather than a guess here. Full detail:
`agents/product-manager/specs/ENG-021-chat-bar-engagement-and-faq-self-service.md`.

## Recommendation

Build now, scoped as above. `M` — touches `restaurant-portal` only: a new
view over already-logged conversation data, plus a new FAQ editor against a
table the app already reads and writes elsewhere in the same portal. No new
backend endpoint or edge function anticipated — both the conversation log
and the FAQ content are already reachable by direct, authenticated Supabase
queries today. $0/month expected. Full PRD:
`agents/product-manager/specs/ENG-021-chat-bar-engagement-and-faq-self-service.md`.
