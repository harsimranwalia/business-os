**You said:** "for catering page need next step/quote generator page which
would have the menu selection for the customer can be sent as link via
sms/email and update the stage on restaurant portal for ones who fill the

restaurant owners can choose to have pricing generator work after the client

**Understood as:** Today a customer who fills out a restaurant's public
catering enquiry page gets nothing back but an on-screen "we'll contact you"
message. This ticket adds a self-service quote-builder step — reachable by
an SMS/email link — where the customer picks menu items and sees a computed
price, opt-in per restaurant. Completing it (or skipping it) moves the
request's stage on restaurant-portal's existing catering board
automatically. Editing/resending an already-sent quote, and wiring the
broader catering pipeline into the general `autopilot` trigger/template
engine, are both named but are later work, not this ticket.

**Requirements:**
1. `[stated]` A customer who submits the catering enquiry form can reach a
   quote-builder step to build a priced order from the restaurant's own
   menu.
2. `[stated]` That step is reachable via an SMS/email link.
3. `[stated]` Restaurant owners can turn this on or off per restaurant; off
   means no change from today.
4. `[stated]` Completing (or skipping) the quote step updates the request's
   stage on restaurant-portal automatically.
5. `[deferred]` Editing/resending an already-sent quote, and deeper
   `autopilot` wiring — separate, later items.

**Two forks bundled as riders, not a second gate** (same bar `ENG-015`'s G1
used):
1. **Who controls the "just contact me" fallback?** Proposed: both — an
   owner-level "Auto-quote" setting (default **off**) gates whether the
   automated link fires at all; independently, the quote-builder page
   itself always carries a "skip — have someone contact me" option for the
   customer. Cheap either way, so building both rather than picking one
   reading over the other.
2. **Menu/pricing model?** Proposed: reuse the restaurant's existing menu at
   existing per-item prices (à la carte) — not a new catering-specific
   pricing model (tiers/minimums). If a real catering price book is wanted,
   that's a materially bigger, separate ticket.

**Evidence checked, not assumed.** `config-site-builder`'s live
`Catering.tsx`/`CateringForm.tsx` post straight to `catering-request`, which
notifies the restaurant owner only — nothing is ever sent back to the
customer beyond the on-page message; the "How It Works" copy already
promises a "Customize Your Menu" step that doesn't exist. `restaurant-
portal`'s catering kanban is a real, shipped 5-stage pipeline with five
hardcoded status strings and no server-side enum, so a sixth ("Quote Sent")
is additive, not a migration. The `autopilot`/`outgoing-communications`
engine is real and mature but today only fires on restaurant-customer

disagreement with the first reading.

# Engineering Task Spec: Website Catering Form & Pipeline Stage Automation

## 1. Summary

Upgrade the existing public catering page (`config-site-builder` / `CateringForm.tsx`) from a static enquiry form into an interactive catering menu selector. When a customer completes this form (or opts for manual contact), the submission must automatically advance the lead stage in the `restaurant-portal` catering pipeline.

---

## 2. Frontend: Public Catering Form (`config-site-builder`)

### Step 1: Packaging & Event Settings

* **Fulfillment Option (Dropdown)**:
* `On-site Catering` (triggers guest count input).
* `Pick up and Delivery` / `Drop-off Trays` (tray/quantity mode).


* **Guest Count Input**:
* Visible when an on-site or per-person package is selected.
* Displays helper note: *"Number of people you are planning for (e.g. 50 people)"*.


* **Package Instructions Banner**:
* Dynamic copy based on the selected package (e.g., *"Select your choice of Appetizers, Curries, Rice & Naan. Salad, Raita, and Dessert are included."*).



### Step 2: Dynamic Categorized Menu Selection

Render menu categories as structured accordion/checkbox groups driven by the restaurant's active menu data:

* **Appetizers (Veg & Non-Veg)**
* **Mains (Paneer, Veg, Chicken, Lamb, Seafood)**
* **Sides (Rice, Naan, Breads)**
* **Desserts & Extras**

**UI Behavior & Rules:**

* **Included vs. Charged Items**:
* If a package allows $N$ selections (e.g., "Choose 2 appetizers"), the first $N$ checked items are included in the base rate.
* Additional checked items display an inline upcharge label (e.g., `+$3.00/person` or tray list price).


* **Portion/Item Customization Box**:
* Clicking an item with variants/dietary notes opens a simple inline note or counter field (e.g., *spiciness level*, *dry vs. gravy*).



### Step 3: Action Buttons & Customer Choice

At the base of the form, provide two explicit paths:

1. **Primary Button (`Submit Quote Request`)**: Submits the chosen items, computes estimated pricing, and requests an official confirmation.
2. **Secondary Fallback (`Skip & Have Someone Contact Me`)**: Bypasses the item picker, takes their contact/event details, and routes them to a manual phone/email follow-up.

---

## 3. Backend: Submission & Automatic Stage Progression

### Endpoint Updates (`POST /api/catering-request`)

Update payload structure to accept structured line-item selections:

```json
{
  "restaurant_id": "rest_123",
  "customer_name": "Jane Doe",
  "customer_email": "jane@example.com",
  "customer_phone": "+16045550199",
  "fulfillment_option": "on_site_catering",
  "guest_count": 75,
  "action_type": "QUOTE_SUBMITTED", // or "MANUAL_CONTACT_REQUESTED"
  "selections": [
    { "category": "Appetizers", "item_id": "app_01", "name": "Vegetable Pakora", "quantity": 1 },
    { "category": "Chicken", "item_id": "chk_04", "name": "Butter Chicken", "quantity": 1 }
  ],
  "customer_notes": "Mild spice preferred for butter chicken."
}

```

### Stage Update Matrix on `restaurant-portal`

Map the submission directly to the restaurant portal kanban board:

| Customer Action | New Stage on Kanban | Triggered System Action |
| --- | --- | --- |
| Submits complete menu selection (`QUOTE_SUBMITTED`) | **`Quote Generated`** (or `Quote Received`) | Stores selected items in lead modal; sends summary SMS/Email to customer and notifies owner dashboard. |
| Clicks skip / manual contact (`MANUAL_CONTACT_REQUESTED`) | **`Contact Requested`** | Flags as lead requiring phone outreach; notifies restaurant team. |
| Leaves page after partial submission (Token link opened) | **`Quote Viewed`** | Updates stage indicator so the owner knows the customer reviewed the options. |

---

## 4. `restaurant-portal` Catering Kanban Changes

1. **Kanban Status Enum**: Add `Quote Generated` and `Contact Requested` to the hardcoded stage list without breaking existing leads.
2. **Catering Request Detail Modal**:
* Display the chosen fulfillment mode and guest count.
* Render an itemized list of customer-selected appetizers, mains, and sides.
* Add an **"Edit Quote"** action button (pre-populates the same selections for the owner to adjust pricing or portions before re-sending).
