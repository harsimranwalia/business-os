## Negative cases in the tests

The one test in this ticket **is** a negative-access case by construction: it
proves a signed-out visitor hitting the protected entry route (`/`) is denied
and redirected to `/login`, rather than proving an authenticated user gets
in. For a smoke-level bar (PRD non-goal: comprehensive coverage) this is the
more security-relevant of the two directions to have checked first — it
guards against the regression that matters most (an unauthenticated visitor
seeing protected content), and a positive authenticated-path test would need
either real credentials or a deeper auth mock, which is out of this ticket's
explicit scope.
