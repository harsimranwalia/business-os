## Regression risk

- **The one real caller of the changed RPC** — traced directly (see AC1
  above), not assumed. Unaffected by construction (named-parameter call).
- **Wider `restaurants` surface** — 30 files across `aiorders-api` query or
  write this table. Not individually reviewed: additive `NOT NULL` columns
  with defaults cannot break an existing `INSERT` (Postgres supplies the
  default), and every consumer is `supabase-js`/PostgREST (JSON-keyed
  responses, not positional tuples), so a column nothing selects is
  invisible to code that doesn't reference it. Confirmed by grep: zero `.ts`
  files anywhere in this repo or its sibling repos reference any of the three
  new column names yet, so there is nothing currently deployed for this
  migration to have broken.
- **Function-overload coexistence** — the one real defect this ticket's own
  testing found (a bare `CREATE OR REPLACE` with a changed arg count creates
  a second overload instead of erroring, silently keeping old callers on the
  stale, ungated function forever). Closed by the migration's own `DROP
  FUNCTION IF EXISTS` with the exact original signature; re-verified this
  pass that the dropped type list matches the true original (principal
  engineer's review, same date) rather than only the ticket's account of it.
