## Regression risk

**AC-9 is the one regression that matters most here** — this ticket touches
the form every restaurant uses today, and the overwhelming majority haven't
opted into the new gate. Traced end-to-end against
`git show origin/main:src/components/CateringForm.tsx` rather than trusting
the diff's own framing: gate-closed labels, required set, submit markup,

in this same hop's code review, not re-derived twice — see that receipt's
own "Read against the ticket and design" section.

No other regression surface: `CateringMenuSelector` is new, and nothing
else in `config-site-builder` imports or calls into it or
`CateringSelection` outside `CateringForm.tsx` (`grep -rn
"CateringMenuSelector\|CateringSelection" src/` — one import site, no other
hits).

## Not automated

**Every acceptance criterion this ticket owns.** `config-site-builder` has
no test runner of any kind — confirmed fresh this round: no `test` script
in `package.json`, no `vitest`/`jest`/`@testing-library/*` dependency
anywhere in it, `find src -iname "*.test.*" -o -iname "*.spec.*"` returns
nothing. This is a materially different gap than `aiorders-api`'s own
(`ENG-031`/`ENG-033`'s test plans) — that project at least has `deno test`
built into its runtime for free; here there is no zero-config path to a
first test at all. Standing one up is new infrastructure, not a test for
this diff, and it is out of this ticket's own scope by the same standing
precedent `ENG-031`/`ENG-033`/`ENG-022`/`ENG-024` already set on
`aiorders-api`'s identical-shaped gap (propose, don't build inline).

but cites it as `"ENG-002's tracked gap"` — **checked, not assumed: that
