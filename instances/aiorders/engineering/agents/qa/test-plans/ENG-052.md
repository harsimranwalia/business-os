## Regression note — the precision fix this ticket itself introduced

Not a fix to a previously-shipped defect (nothing has shipped on this table
in production yet — `loyalty_ledger_entries` is 0 rows live), so this isn't
"a bug fix with no regression test" in the classic sense. Graded instead as
the standard asks of any fix found pre-ship: **the test targets the threat,
not the column type.** Configured a restaurant at the exact sub-cent rate
(`0.0025`) that would silently round to `0.00` under the pre-widening
`numeric(5,2)`, and confirmed the stored value is `0.0025`, not `0.00` — a
mutation aimed at the regression itself, not an assertion that would pass
regardless of whether the fix were present.
