## Regression check — the balance-summing defect caught before it shipped

`readBalance`'s first draft summed from the same capped, 500-row `entries`
list it returns for display — correct at zero rows, silently wrong the
moment one diner/restaurant pair exceeded the cap. Fixed by splitting into
an unbounded narrow sum query and a separately-capped display query.
**Watched the fake distinguish the two queries, not just the assertion**:
`makeLedgerTable`'s own `.limit(n)` is tracked per query-chain instance, so
a fixture of 505 single-point rows genuinely returns 505 to the unbounded
sum path and ≤500 to the capped path inside the fake, the same shape a real
Postgres query would produce — this is a real regression test, not a
symbolic one that would pass against the reverted (buggy) code by
construction.
