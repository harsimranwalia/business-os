## Round-1 gaps this ticket exists to close

Automatic-failure #10 (code review round 1, 2026-08-30): zero test coverage
on the new admin-gated write path. A first attempt (`dc6972a`, found already
pushed) covered three of four named `hasInfluencerAdminAccess` cases and
every field's validation, but not the missing/undefined-profile case or the
allowlist-enforcement proof. Closed by `57f8c4b`:
`hasInfluencerAdminAccess rejects a missing profile` and
`handleInfluencers PATCH strips fields outside the editable allowlist
before writing` — both hand-traced against `influencers.ts` at HEAD, both
correct.

A second, independent round-1 finding — not a coverage gap but a real
correctness bug — is not backend-testable at all: `Influencers.tsx`'s
`accepts_paid`/`accepts_barter` defaulted via `?? !barter_visit`, fabricating
a value for any influencer whose preference was genuinely null. Fixed in
`aiorders-admin-hub@63be255` (see code review, Verification section, for the
independent re-trace); no automated regression test exists for it because
`aiorders-admin-hub` has no test framework at all — see Not automated below.

## Regression risk

Additive on both repos. `aiorders-api`: two new nullable/defaulted columns
plus a backward-compatible additive backfill of `accepts_paid`/
`accepts_barter` from `barter_visit`, which is left untouched — no existing
reader of `barter_visit` changes behavior. New route is an added `else if`
branch in `index.ts`; every existing route above it in the chain is
unreached by this diff. `aiorders-admin-hub`: the only removed code is a
read-only "Location Preferences" display block, superseded by the new
editable region field in the same dialog position — no information lost,
confirmed by reading both the removed block and its replacement side by
side. No existing prop, fetch call, or unrelated component is touched.
