## PR body (for release-readiness to use verbatim)

**What it does:** Adds `faqs` as a third `EDITABLE_PAGES` entry on
`brand-portal`'s `update_website_content`/`get_website_content` actions, so
the owner's own JWT can write `restaurant_website.faqs` — the column the
chat-bar bot already reads from — through an existing, already-ownership-
checked action. No new route, no new action, no signature change.

**What it deliberately does not do:** No change to `verifyRestaurantAccess`/
`requireRestaurantAccess` or either action's ownership check (`ENG-022`,
already shipped). No change to `CateringPageContent.faqs` (the unrelated,
catering-landing-page FAQ list) — this is a new, separate top-level column.
Does not fix the pre-existing `deno check` noise this file already carries.

**Uncertainties / what to look at hardest:** The one new `deno check` error
(`data?.faqs` on `GenericStringError`) is expected noise, not a regression —
see this notebook's Self-test section for the exact baseline delta (7→8,
single file; 33→34, whole directory) if a reviewer wants to verify rather
than trust this note.
