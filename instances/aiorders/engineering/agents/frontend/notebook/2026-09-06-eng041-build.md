## What was built

Per the design's Components table (rows 4-9):

- `src/types/website.ts` — new `WebsiteFaq` interface (deliberately separate
  from `CateringFaq`, same shape) and `WebsiteContent.faqs: WebsiteFaq[] |
  null`.
- `src/components/website/WebsiteFaqForm.tsx` — new. Mirrors
  `CateringPageForm.tsx`'s add/edit/remove FAQ block (Card, per-row
  question/answer, add/delete buttons, blank-row filtering on submit,
  spread-based per-item patch so unknown keys round-trip). Adds the
  `faqDraft` seeding this ticket needs: a `useEffect` keyed on
  `[content, faqDraft]` resyncs `form` from `content` on every arrival and,
  the first time only (guarded by a ref), appends one entry seeded with the
  carried question and focuses its answer field (`autoFocus` on the row at
  the captured draft index). Guarding by ref rather than letting a second
  effect race the content-sync one was a deliberate choice — an unguarded
  append effect and the content-resync effect both fire on mount, and
  whichever runs second silently wins.
- `src/pages/website/Index.tsx` — third `TabsTrigger`/`TabsContent`
  (`grid-cols-2 → grid-cols-3`). Captures `location.state?.faqDraft` **once**
  via a lazy `useState` initializer (not re-read afterward), sets the Tabs'
  `defaultValue` to `faqs` when a draft is present, and clears the location
  state on mount (`navigate(location.pathname, { replace: true, state: null
  })`) so a refresh doesn't re-add the draft — the local captured copy
  survives that clear since it isn't sourced from `location.state` a second
  time.
- `src/pages/questions/Index.tsx` — new. `useInfiniteQuery` (not a
  hand-rolled accumulator — this repo has no prior use of it, but it's an
  existing `@tanstack/react-query` dependency and is exactly the "keyset,
  append" shape the design's own Interfaces section asks for:
  `getNextPageParam` returns `undefined`, hiding "Load older," when the last
  page was short of 100 rows *or* the oldest loaded session's `updated_at`
  is null — both conditions from the design, independently). The normaliser
  (`flattenSession`) follows the design's own table exactly: non-array
  `messages` → zero rows, non-`user`/malformed elements skipped, unparseable
  `timestamp` falls back to the session's `updated_at`, and a
  still-null-after-fallback row sorts last rather than being dropped
  (`sortNewestFirst`'s comparator, nulls ordered after any real date). The
  query throws from `queryFn` on a PostgREST error (logging only
  `error.code`, never the payload or question text) rather than swallowing
  it into `[]`, per the design's explicit instruction not to copy
  `feedback/Index.tsx`'s idiom here — a failed query must not read as "no
  activity" (AC2). "Add to FAQs" calls `navigate('/website', { state: {
  faqDraft: { question: text } } })` — never a query parameter.
- `src/App.tsx` — one nested route, `questions`, under the existing
  `DashboardLayout` parent, alongside `website`/`feedback`.
- `src/components/layout/Sidebar.tsx` — one `navItemsAfter` entry,
  "Customer Questions" (`MessageCircleQuestion`, not reusing `HelpCircle` or
  `MessageSquare` — both already assigned to Help and Feedback
  respectively), placed directly above Feedback per the design.

**Not touched**, per the design's explicit instruction: `CateringPageForm.tsx`
/ `CateringFaq` (a different, catering-landing-page-only FAQ list — mirrored,
not wired into), `brand-portal/index.ts` (routing already exists),
`aiorders-admin-hub/RestaurantAIWebsite.tsx` (AC5 is satisfied by not
building a second store).

## Tests added

- `WebsiteFaqForm.test.tsx`: the draft-seeding effect appends the carried
  question alongside existing FAQs without dropping them; a post-save
  content refetch does not re-append the draft a second time; blank rows
  are filtered on save. The first two are this ticket's one genuinely new,
  regression-shaped piece of logic — same reasoning `CateringPageForm`'s own
  existing regression test used for its seeding effect.
- `pages/questions/Index.test.tsx`: user-only, newest-first flattening
  across sessions with the assistant turn excluded (AC6); the empty state
  when there's no extractable question; a distinct error state with a
  retry button rather than the empty state, when the query fails (AC2); a
  malformed session (`messages` not an array) contributes nothing while a
  well-formed sibling session still renders; the "Add to FAQs" hand-off
  calls `navigate` with the question in `state`, never in the path/query.

Pagination ("Load older" itself, beyond the two independent hide conditions
already covered by the normaliser/comparator unit-level reasoning above) is
not separately exercised end-to-end — noted for QA's own test-plan rather
than expanded here.

## PR body (for release-readiness to use verbatim)

**What it does:** Adds a `/questions` page (bounded, keyset-paginated read of
`ai_conversations`, RLS + explicit `restaurant_id` filter) and a third FAQs
tab on the Website page (`restaurant_website.faqs` via `ENG-040`'s widened
`update_website_content`), joined by an "Add to FAQs" hand-off that carries
the question through react-router location state.

**What it deliberately does not do:** No change to `CateringPageForm.tsx`/
`CateringFaq` (different column, different consumer — mirrored, not
extended). No change to `aiorders-admin-hub`'s staff FAQ editor. No
deduplication, clustering, redaction, or export of questions (PRD
non-goals). No change to retention/`cleanup_old_ai_conversations`.

**Uncertainties / what to look at hardest:** `WebsiteFaqForm`'s
draft-consumption guard (a ref, not component unmount/remount) is the one
piece of logic in this ticket without a design-doc line-item precedent to
check against — see this notebook's own "What was built" section for the
race it avoids and the test that pins it down.
