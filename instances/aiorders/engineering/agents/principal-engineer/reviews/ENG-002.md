## Line-level

- `vite.config.ts` — imports `defineConfig` from `vitest/config` (a superset
  of Vite's own, adding the `test` key's types) instead of `vite`; correct,
  and the only way to get the `test` block type-checked at all.
- `src/test/setup.ts` — the three polyfills (`matchMedia`, `ResizeObserver`,
  `IntersectionObserver`) are each guarded by an existence check rather than
  unconditionally overwritten, and the comment names exactly which real
  components touch each on mount (Radix Tabs, embla-carousel, framer-motion).
  That's the non-obvious constraint a future maintainer would otherwise have
  to rediscover by reading a cryptic jsdom stack trace.
- `src/App.test.tsx` — mocks `@/integrations/supabase/client`, the actual
  network boundary, not a layer above it. Traced this independently through
  `src/context/auth/supabaseAuth.ts` (`checkSession` calls
  `supabase.auth.getSession()`) and `src/context/auth/AuthContext.tsx`
  (`setupAuthSubscription` wraps `supabase.auth.onAuthStateChange`) — both
  mocked methods are exactly the ones the real code calls. Mocking here
  rather than mocking `checkSession` itself means the test still exercises
  the department's own auth-state-resolution logic, not just the component
  tree.
