## Design conformance

Checked against
`agents/architect/designs/ENG-009-influencer-engagement-info.md` and the
PRD's 4 acceptance criteria:

- **AC1** (activity signal derived from history, displayed) —
  `getInfluencerActivity` aggregates `influencer_invitations` server-side
  with the service-role client (required — that table has no staff/admin
  `SELECT` policy, confirmed against the design's own live-RLS finding);
  frontend renders it as a table column and a dialog block, both gated on
  `invitations > 0`.
- **AC2/AC3** (social figure: set when unset, updated when already set,
  board reflects it) — `followers`/`engagement` reuse the existing columns
  through the same generic `update()` mechanism every other editable field
  uses; no separate code path for "first set" vs. "edit", so both
  criteria share one proof.
- **AC4** (shows when last updated) — `social_stats_updated_at` stamped
  server-side whenever either numeric field is written, never client-sent;
  rendered in the dialog as "Updated {date}"; "Not set" shown in place of
  a fabricated `0`/`0.0%` until the timestamp exists.
- **Two readings shown distinctly** (inferred requirement 3) — activity
  (invitations/visits/response rate) and the social figure (followers/
  engagement/platform) are visually and structurally separate blocks in
  both the table and the dialog; no shared control or merged number.

One flagged, non-blocking divergence from the design's literal text, not
newly found this round (present and already reasoned through in round 1's
own build-hop entry, re-checked here rather than taken on trust): the
design specifies `social_stats_updated_at` set "when either numeric field
is present **and changed**"; the shipped code stamps on **present** only,
since no other field in this handler diffs incoming-vs-current before
writing and adding one only for these two fields would introduce a
read-modify-write race the surrounding code doesn't have elsewhere.
Covered by its own scoping test (`does not stamp ... when neither social
field is written`). Functionally honest for the design's own stated goal —
accepted, not a fail.
