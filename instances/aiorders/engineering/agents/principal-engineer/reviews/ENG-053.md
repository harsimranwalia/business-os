## Round 1's finding, verified fixed by reading the tests against the finding's own requirement — not accepted because the count is green

Round 1's fix list named four items. Checked each against the actual diff,
not against the ticket's own account of it:

1. **Missing `restaurant_id`/`code`/`idempotency_key`, and 7 invalid `points`
   values, each asserts the rejection message *and* `rpcCalls.length === 0`.**
   Read the assertions directly (lines 278–340 of the new diff): every one of
   the eleven new negative-input tests calls `assertRejects` with the exact
   message the implementation throws, then separately asserts the RPC spy
   array is empty — this is the design's own load-bearing "no RPC call made"
   claim, proven as a call-count property rather than inferred from the throw
   alone. The 7-value `INVALID_POINTS` array (`0, -5, NaN, Infinity, "10",
   null, undefined`) matches `record_dine_in_earn`'s own `INVALID_AMOUNTS`
   pattern in this same file exactly — no new idiom invented.
2. **Access denied propagates, RPC never called.** One test, same
   `rpcCalls.length === 0` proof alongside the `assertRejects`.
3. **All four RPC outcomes, via a stubbed `.rpc()` result each.**
   `invalid_code`/`not_enrolled` assert the exact `{success, result}` shape
   with no `balance` key *and* `ledger.queryCount() === 0` — proving
   `readBalance` genuinely wasn't reached, not just that the response happens
   to lack the field. `insufficient_balance`/`redeemed` assert the correct
   summed balance (`25` from a 20+5 seed; `10` from a 20-10 seed) *and*
   `queryCount() > 0`. This is a real, mutation-sensitive test: swapping which
   two branches attach balance, or swapping the sign of the seeded redemption
   row, changes the expected number and would fail — not an assertion that
   passes regardless of the implementation.
4. **`handleLoyalty` dispatch test renamed and extended.** `routes both
   actions` → `routes all three actions`, now also calls `redeem_points`
   through the switch and asserts exactly one `.rpc()` call reaches
   `redeem_points_if_eligible` — closes the stale-name finding and proves the
   router wiring (`index.ts`'s `+1 case` line, already reviewed clean in round
   1) actually reaches the handler end to end.
